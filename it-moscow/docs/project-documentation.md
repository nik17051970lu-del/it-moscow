# Документация проекта «Стол заказов проектов · IT.МОСКВА»

Версия: учебный MVP. Дата: 27.11.2026. Документ описывает фактический код проекта, функции и порядок проверки.

## 1. Назначение и границы

Сервис помогает студентам колледжа искать и предлагать учебники, конспекты и материалы для проектов. Пользователь просматривает каталог, применяет фильтры, открывает карточку, оставляет локальный отклик или публикует объявление. Доступны форма вопроса и деморегистрация.

Express раздаёт сайт по HTTP. Серверной базы данных, настоящей аутентификации, общей доски для разных устройств и доставки сообщений автору пока нет. Отзывы пользователей исключены из требований. PO, дизайнер-аналитик и разработчик — роли команды; разграничение прав пользователей на сервере не реализовано.

## 2. Запуск и структура

Нужен Node.js 22 или новее. Команды выполняются в корне репозитория, рядом с package.json:

```sh
npm ci
npm start
```

Откройте http://127.0.0.1:3000/. Карточка-пример: http://127.0.0.1:3000/material.html?id=demo-1. Остановка: Ctrl+C. `npm run dev` следит за изменением файлов Node.js; изменение HTML/CSS проверяется обновлением страницы. Другой порт на macOS/Linux: `PORT=3001 npm start`; PowerShell: `$env:PORT=3001; npm start`.

## 3. Сервер и маршруты

`createApp()` в app.js возвращает приложение Express и не открывает порт. Это позволяет тестировать приложение на свободном порту. server.js запускает его с HOST=127.0.0.1 и PORT=3000 по умолчанию. PORT должен быть целым числом 1–65535; занятый порт приводит к понятному сообщению и коду ошибки процесса. SIGINT/SIGTERM закрывают HTTP-сервер.

| Метод и адрес | Результат |
|---|---|
| GET / и /index.html | Главная страница, 200 |
| GET /material.html?id=demo-1 | HTML карточки, 200; нужное объявление выбирает JS в браузере |
| GET /styles/*, /scripts/*, /assets/* | Существующие статические файлы из front |
| GET /api/health | JSON: status=ok и название проекта |
| Неизвестный адрес | HTML-страница «Страница не найдена», 404 |
| POST /api/registration | 404: такого API пока нет |

Статическая папка задана абсолютным путём от __dirname. Сервер не публикует весь репозиторий: package.json, server.js, .git и docs недоступны по HTTP. Заголовок X-Powered-By отключён. Обработчик ошибок возвращает статус 4xx для соответствующих ошибок запроса или 500 без выдачи стека клиенту. Обычная 404 сервера отличается от карточки с неизвестным id: material.html загружается, а сообщение о ненайденном материале показывает клиент.

### Обработчики форм и событий

- Публикация: preventDefault → validateForm → новая запись в board.own → saveBoard → очистка черновика → перерисовка каталога. При сбое хранения запись остаётся только до закрытия страницы.
- Форма вопроса: проверка имени и сообщения → добавление локальной записи с createdAt → очистка формы после успеха. Сообщение администрации не отправляется.
- Регистрация: проверка пяти полей → сохранение name/email/group/createdAt → очистка формы и показ демопрофиля. Пароли не включаются в объект сохранения и очищаются при закрытии диалога.
- blur/change проверяют поле; input повторно проверяет его, если уже выставлено aria-invalid. При изменении пароля перепроверяется подтверждение.
- input публикации сохраняет черновик; input поиска, change категории и click типа сохраняют фильтры. При старте корректные сохранённые значения применяются повторно.

## 5. Листинги функций

Ниже приведены реальные функции из main.js на дату документа. Полные исходники доступны по ссылкам в разделе 2. Зависимости перечислены перед каждым листингом.

### loadBoard

Использует storageKey и localStorage; позволяет открыть каталог при ошибке чтения.

```js
function loadBoard() {
  try {
    const value = JSON.parse(localStorage.getItem(storageKey));
    return { own: Array.isArray(value?.own) ? value.own : [], replies: Array.isArray(value?.replies) ? value.replies : [] };
  } catch {
    return { own: [], replies: [] };
  }
}
```

### saveBoard

Использует storageKey, board и localStorage; вызывающий код обрабатывает false.

```js
function saveBoard() {
  try {
    localStorage.setItem(storageKey, JSON.stringify(board));
    return true;
  } catch {
    return false;
  }
}
```

### validationMessage

Использует объект правила из rules; совпадение паролей отдельно проверяет validateField.

```js
function validationMessage(value, rule) {
  const text = rule.raw ? value : value.trim();
  if (!text) return 'Заполни это поле.';
  if (rule.options && !rule.options.includes(text)) return 'Выбери значение из списка.';
  if (rule.min && text.length < rule.min) return 'Введи не менее ' + rule.min + ' символов.';
  if (rule.max && text.length > rule.max) return 'Не более ' + rule.max + ' символов.';
  if (rule.email && !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(text)) return 'Введи email в формате student@example.com.';
  if (rule.password && (!/\p{L}/u.test(text) || !/[0-9]/.test(text))) return 'Добавь хотя бы одну букву и одну цифру.';
  return '';
}
```

### validateForm

Использует rules и validateField; возвращает true только при отсутствии ошибок.

```js
function validateForm(target) {
  let first;
  for (const [name, rule] of Object.entries(rules[target.id])) {
    const field = target.elements.namedItem(name);
    if (!validateField(field, rule) && !first) first = field;
  }
  if (first) first.focus();
  return !first;
}
```

## 6. Поля, ограничения и хранение

| Форма | Проверяемые значения |
|---|---|
| Объявление | type: offer/request; category: Книги/Конспекты/Материалы; title: 1–80; course: 1–55; description: 1–320 символов |
| Вопрос | name: 2–50; message: 10–500 символов |
| Регистрация | studentName: 2–50; email: до 254, простой формат адреса; group: 2–20; password: 8–128, минимум буква и цифра; confirmPassword совпадает с password |

Для обычного текста удаляются пробелы по краям; пароль проверяется без trim. Пустые обязательные значения отклоняются. Ошибки представлены текстом, aria-invalid и aria-describedby. Это клиентская валидация учебного демо, она не заменяет серверные проверки и аутентификацию.

| Ключ localStorage | Данные |
|---|---|
| it-moscow.exchange.v1 | own: собственные объявления; replies: id материалов с откликом |
| it-moscow.feedback.v1 | Массив вопросов: kind, name, message, createdAt |
| it-moscow.profile.v1 | name, email, group, createdAt; без пароля |
| it-moscow.publish-draft.v1 | type, category, title, course, description; очищается после публикации |
| it-moscow.filters.v1 | search, category, type |

Объявление содержит id, type, category, title, course, description; собственное — own=true, закрытое — closed=true. Демообъявления seed описаны в listings.js и не являются серверными данными. Создание записи использует время и случайную строку для локального id.

Очистка данных сайта удаляет локальные записи. Разные браузеры, профили, адреса и порты имеют отдельные хранилища. Для проверки всех страниц используйте один origin: http://127.0.0.1:3000. Не храните в учебном демо конфиденциальные данные. При заблокированном/переполненном localStorage действия могут не сохраниться; интерфейс показывает сообщение в основных сценариях записи.

## 9. Следующий этап: база данных

База данных пока не подключена; приведённый ниже план не является реализованной схемой или API. Для перехода к общей доске требуется согласовать серверную регистрацию, роли и владение данными; выбрать СУБД; подготовить миграции и резервное копирование; перенести объявления и отклики в серверное хранилище; добавить проверку входных данных и прав на сервере, затем интеграционные тесты. Пароли на сервере должны обрабатываться через подходящий алгоритм хеширования и не возвращаться клиенту.

Предлагаемые сущности для обсуждения: users (студенты), listings (объявления с автором и статусом), responses (отклики с пользователем и объявлением), questions (обращения). До реализации этого этапа нельзя считать локальный демопрофиль настоящим входом, а локальный отклик — отправленным другому студенту.
